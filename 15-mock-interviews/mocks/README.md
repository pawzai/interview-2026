# Full mock loops

Six complete interview loops, five rounds each. Every round has a duration, an interviewer persona, a verbatim opening prompt, a **follow-up ladder** of three levels, a model-answer outline, a curveball to inject at a stated minute, and a rubric.

These are the rehearsal. [questions.md](../questions.md) trains individual answers; a loop trains the thing that actually fails on the day - **structure under fatigue across five consecutive rounds** (Q204).

| Loop | Archetype | Weighting |
| --- | --- | --- |
| [loop-01](loop-01-java-platform-principal.md) | Java and Spring platform principal | Language and framework depth, platform thinking, code review |
| [loop-02](loop-02-solution-architect-aws.md) | Solution architect, AWS-heavy | Cloud architecture, cost, migration, stakeholder communication |
| [loop-03](loop-03-ai-engineering-lead.md) | AI engineering lead | GenAI, RAG, agents, evaluation discipline, AI security |
| [loop-04](loop-04-technical-lead-people.md) | Technical lead with a people focus | Leadership, conflict, mentoring, delivery, incident command |
| [loop-05](loop-05-staff-design-heavy.md) | Staff-level, design-heavy | Two design rounds, distributed data, scale arithmetic |
| [loop-06](loop-06-final-exec-committee.md) | Final loop and hiring committee | Executive communication, level defence, bar raiser, negotiation |

## How to run one

**With a partner.** Give them the loop file. They do not need domain expertise - the file contains the prompts, the ladder and the rubric, and Q14 explains how to make a non-expert's score meaningful. Ask them not to read the model-answer outline aloud.

**Alone.** Set a timer per round, read only the opening prompt, speak the answer out loud, and record. Read the ladder only after your first answer, then answer each level cold. Score yourself against [scoring-sheet.md](scoring-sheet.md) from the **recording**, not from memory - the memory is systematically generous (Q11).

**Rules that make it worth doing.**

- Keep the breaks. Five to ten minutes between rounds, exactly as on the day. Running five rounds back to back trains a day that does not exist, and running them across a week trains nothing about fatigue.
- Do not pause the clock, do not restart a round, and do not look anything up mid-round.
- Speak everything. Silent reading is not practice.
- Take the curveball when the file says, even if it is inconvenient. That is the point of it.
- Finish a bad round. The recovery is the most valuable thing in the exercise (Q193, S7).

**Afterwards**, write one page: the three weakest moments, the answers where you had no number, and anything you said that you could not have defended under one more "why". That page is the input to the next week's preparation.

---

## Choosing a loop

Pick by the **role you are interviewing for**, not by the topic you enjoy. If the job description is a platform role, run loop-01 even if your AWS is weaker - the loop should look like the day.

Run at least two different loops before a real interview. A single loop run twice measures recall (Q12).

Loop-06 is worth running before any loop you care about, regardless of archetype, because the level defence and the negotiation rehearsal transfer to every role.

---

## Rounds are reused deliberately

Some rounds appear in more than one loop with a different interviewer persona and a different follow-up ladder - a design round in loop-02 and loop-05, for instance. That is intentional. The same question asked by a cost-focused architect and by a distributed-systems specialist is a different round, and noticing that in the first two minutes is a skill worth training (Q2).
